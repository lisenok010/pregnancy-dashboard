# 🚀 Как опубликовать дашборд на GitHub Pages

Подробная инструкция от нуля. Время: ~15 минут.
**GitHub в России работает без VPN.**

---

## 📋 Что тебе понадобится

- Аккаунт на GitHub (бесплатный)
- Этот архив с проектом

---

## Шаг 1. Создай аккаунт на GitHub

1. Открой [github.com](https://github.com)
2. Нажми **Sign up** в правом верхнем углу
3. Введи email, пароль, придумай username (например, `anna-sizova`) — он попадёт в URL дашборда
4. Подтверди email

---

## Шаг 2. Создай репозиторий

1. После входа нажми **+** в правом верхнем углу → **New repository**
2. **Repository name:** `pregnancy-dashboard` (если хочешь другое имя — запомни его, понадобится дальше)
3. Поставь галочку **Public** (для GitHub Pages бесплатно нужен публичный репозиторий)
   - ⚠️ **Важно:** публичный репо означает, что код виден всем. Если хочешь private — нужен GitHub Pro ($4/мес) или попроси меня собрать в HTML-файл.
4. **НЕ** ставь галочку «Add a README file»
5. Нажми **Create repository**

---

## Шаг 3. Загрузи файлы проекта

### Способ А — через сайт GitHub (самый простой, без программ)

1. На странице нового репозитория нажми ссылку **uploading an existing file**
2. Распакуй скачанный архив на компьютере
3. Перетащи **все файлы и папки** из распакованной папки в окно браузера
   - ⚠️ Важно: перетаскивай содержимое папки, а не саму папку
   - ⚠️ Папки `.github` и `src` тоже должны быть в списке
4. Внизу страницы напиши «initial commit» в поле сообщения
5. Нажми **Commit changes**

### Способ Б — через командную строку (для тех, кто умеет)

```bash
cd dashboard-deploy
git init
git add .
git commit -m "initial commit"
git branch -M main
git remote add origin https://github.com/ТВОЙ_USERNAME/pregnancy-dashboard.git
git push -u origin main
```

---

## Шаг 4. Если ты выбрала другое имя репозитория

Если в Шаге 2 ты назвала репо НЕ `pregnancy-dashboard`, открой файл `vite.config.js` (можно прямо на GitHub: клик по файлу → карандаш «Edit») и измени строчку:

```js
base: '/pregnancy-dashboard/',
```

на

```js
base: '/ТВОЁ_ИМЯ_РЕПО/',
```

Косые черты обязательны. Сохрани (**Commit changes**).

---

## Шаг 5. Включи GitHub Pages

1. На странице репозитория зайди в **Settings** (вкладка справа сверху)
2. В левом меню найди **Pages**
3. В разделе **Build and deployment** → **Source** выбери **GitHub Actions**
4. Готово, больше ничего не настраивай

---

## Шаг 6. Дождись сборки

1. Вернись на главную страницу репозитория
2. Перейди во вкладку **Actions** (вверху)
3. Увидишь запущенный процесс «Deploy to GitHub Pages»
4. Подожди 1-3 минуты, пока появится зелёная галочка ✅
5. Если будет красный крестик ❌ — кликни, посмотри что не так, и напиши мне ошибку

---

## Шаг 7. Открой ссылку 🎉

Твой дашборд будет доступен по адресу:

```
https://ТВОЙ_USERNAME.github.io/pregnancy-dashboard/
```

Например:
```
https://anna-sizova.github.io/pregnancy-dashboard/
```

Сохрани в закладки, отправь мужу/врачу — открывается с любого устройства, без VPN, без приложений.

---

## 🔄 Как обновлять дашборд

Когда я пришлю тебе новую версию `App.jsx` (после новых анализов или УЗИ):

1. На GitHub зайди в папку `src`
2. Открой файл `App.jsx`
3. Нажми карандаш **Edit** (справа сверху)
4. Удали всё содержимое, вставь новое
5. Внизу нажми **Commit changes**
6. Через 1-2 минуты дашборд обновится сам — обнови вкладку в браузере

## ⚠️ Безопасность — прочитай!

Публичная ссылка означает, что любой, кто её узнает или нагуглит твой репозиторий, увидит:

- Твоё ФИО (Анна Сизова)
- Дату рождения
- Возраст
- Все медицинские показатели
- Имена врачей и клиник

**Что можно сделать:**

1. **Самое простое — оставить как есть.** Чтобы найти именно твой дашборд, нужно знать точный URL. Поисковики его не индексируют, если репо новый.

2. **Обезличить данные** — попроси меня заменить имя на «А.» и убрать дату рождения. Я подготовлю версию за минуту.

3. **Защитить паролем** — GitHub Pages пароль не поддерживает. Если нужен пароль — перейти на Cloudflare Pages с Access (тоже без VPN).

4. **Сделать private** — нужен GitHub Pro ($4/мес).

---

## 🆘 Если что-то не работает

**«Страница не найдена / 404»**
- Проверь Шаг 5 (источник GitHub Actions)
- Проверь Шаг 4 (имя репо в `base`)
- Подожди ещё 2-3 минуты после первого деплоя

**«Белая страница»**
- Скорее всего неправильный `base` в `vite.config.js`. Должно быть `/имя-репо/` со слэшами с обеих сторон.

**Сборка падает (красный крестик в Actions)**
- Скопируй текст ошибки и пришли мне — разберёмся
